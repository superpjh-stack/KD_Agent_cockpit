# 모바일 음성 중심 리팩토링

## 사용자 흐름

모바일에서 숨겨졌던 음성 패널을 대화 위로 옮겼다. 마이크 입력과 정지 안내, 질문 예시, 인식 결과 확인, 전송 버튼을 한곳에 배치했다. 글 입력은 접이식 보조 입력으로 제공한다. 대화창의 모바일 고정 높이를 제거해 음성과 답변을 페이지 스크롤로 함께 읽을 수 있게 했다.

녹음 종료 후 자동으로 인식하므로 기존 ‘글자로 변환’ 버튼이 필요 없다. 인식 전 외부 전송 안내를 표시하고 실제 질문은 확인 버튼을 눌러야 전송한다. 숫자·프로젝트 번호를 수정할 수 있다. 응답은 기본으로 음성도 준비하지만 설정을 끌 수 있으며, 재생은 사용자가 누른다. 브라우저 자동 재생 차단에 의존하지 않는 흐름이다.

## 코드와 상태

`voice_panel.py`로 음성 화면과 인식 상태 처리를 분리했다. 녹음 해시를 전송·새 대화 뒤에도 유지해 기존 녹음이 재인식되지 않게 했다. 오류도 상태에 보관하고 명시적 재시도 또는 새 녹음에서 다시 인식한다. 녹음 위젯 키는 그대로 유지한다. TTS 실패는 이미 받은 텍스트 답변을 보존하며 재시도 버튼을 제공한다. 음성 데이터는 기존처럼 세션 메모리에서만 보관한다.

## 검증

로컬 Chrome의 390×844, 360×780 뷰포트에서 음성 입력이 첫 화면에 표시되고 페이지 가로 넘침이 없음을 확인했다. 1365×900 데스크톱 배치도 확인했다. 모바일 시각 검수 중 발견한 안내문 간격을 수정했고, 브라우저 오류 로그는 없었다. 검수 브라우저에는 자동 번역이 적용되어 화면 문구가 소스와 다르게 표시되는 현상이 있었다.

자동 테스트는 중복 인식 방지, 실패 후 명시적 재시도, 초안 보존, 전송 전 검토와 전송 후 초기화, 음성 합성 실패 시 텍스트 답변 보존을 포함한다. 실제 휴대폰 마이크·OpenAI 음성 호출·모바일 Safari 재생 검증 및 운영 배포는 별도로 필요하다. HTTPS 접속, 마이크 권한 허용, 한국어 숫자와 LOT 인식 정확도를 실제 기기에서 확인해야 한다.

## 다른 회사 재사용

음성 입력→인식 내용 확인→전송→답변 재생 흐름과 상태 처리는 재사용 가능하다. 회사별로 헤더, 질문 예시, 음성 인식의 회사·공정 용어를 교체한다. 실시간 통화형 음성 대화가 아니라 녹음 기반 업무 질문 인터페이스다.
