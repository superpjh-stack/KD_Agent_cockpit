# 경동글로벌텍 에이전트 V3

make_best2_agent의 연구소·보고서 패턴을 기존 경동 React/FastAPI 앱에 병합했다. 기존 복합질문 LangGraph, 음성, 지식베이스, 조회 도구와 원본 DB를 유지한다. 회사별 템플릿을 경동 업무에 맞춰 작성했으며 다른 회사의 자료는 이식하지 않았다.

## 연구소

품질 원인 조사, 제조 개선 공방, 프로젝트 여정, 업무 브리핑을 제공한다. `POST /api/studio`는 collect → draft → verify LangGraph로 원본 근거 ID를 연결하고 사실·원인 후보·창작·미확인을 나눈다. 근거 연결 검사는 제조 안전성 인증이 아니다. 품질 조사와 여정은 프로젝트 ID가 필요하다. 공방 기본값은 기획 템플릿이며, 서버 AI 설정 시 선택적으로 새 콘셉트를 작성한다. AI 실패를 템플릿 성공으로 숨기지 않는다.

## 보고서

`POST /api/reports`와 대화 요청으로 아래 다섯 종류를 생성한다. 모든 종류는 전체 또는 단일 `project_id` 범위를 지원한다.

| kind | 내용 |
| --- | --- |
| projects | 고객, 설비 유형, 납기, 상태, 진행률 |
| materials | 자재 LOT, 규격, 수량·단위, MTC, 재고 상태, 입고검사 |
| operations | 공정별 계획·실제/누적 공수, 차이, 상태, 납기 |
| fat | 시험 항목, 측정값·단위, 기준, 판정, 조치 계획 |
| quotes | 수주금액, 예측원가·이익률·납기, 모델 상태 |

`GET /api/reports/{id}/xlsx|pdf`에서 저장된 스냅샷을 다운로드한다. Excel에는 기본 보고서 양식과 원본 스냅샷 시트가 포함된다. PDF는 반복 머리말, 페이지 번호, 한국어 텍스트를 지원한다. 특정 고객의 승인 양식을 복제한 것은 아니다.

생성 상태·오류·완료 시각·ID·다운로드 버튼을 표시한다. 생성 이후 원본이 바뀌어도 보고서는 동일한 저장 스냅샷을 사용한다. 자재별 검사 여러 건으로 발생한 반복 수량을 합산하지 않는다. 미입력과 0을 구분한다. 진행 공수로 확정 효율을 계산하지 않고 예측값을 실제 원가로 표시하지 않는다.

현재 데이터·문서는 기존 앱과 동일하게 가상·미승인 샘플로 표시한다. 원본 기준일은 미등록이다. 조회한 납기일을 실제 생산일로 취급하지 않는다. 날짜·기간별 보고서는 지원하지 않으며 대화에서 명시적으로 안내한다. 일일생산보고서는 생산일자·수량·단위가 연결될 때 별도 구현해야 한다.

## 저장 및 인증

기존 SQLite/PostgreSQL 연결 어댑터를 사용한다. 보고서 최초 생성/다운로드 때 `v3_report_exports` 테이블을 생성한다. 기존 제조 테이블을 수정하지 않는다. 기존 회사 접근 코드 인증을 그대로 적용하며 API 응답은 no-store로 설정한다. 개인 계정 체계가 없어 사용자별 파일 소유권을 제공한다고 주장하지 않는다. 보관 기간 정책은 별도 결정이 필요하다.
