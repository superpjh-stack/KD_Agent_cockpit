# 경동글로벌텍 AI Agent V2

`new-agent-maker`의 니즈푸드 기준과 2026-10-11 설치 스킬 지침을 반영한 React 19 · TypeScript · Vite 7 · FastAPI 화면입니다. 기존 Streamlit 앱과 경동글로벌텍의 읽기 전용 저장소·조회 도구를 재사용합니다. 니즈푸드의 급식/김치 데이터 모델은 사용하지 않습니다.

## 실행

프로젝트 루트에서 실행합니다. Python 3.12 권장(현재 로컬 Python 3.9에서도 테스트), Node 22.12 이상이 필요합니다.

```bash
.venv/bin/pip install -r v2/requirements.txt
npm ci --prefix v2/web
npm run build --prefix v2/web
DATABASE_URL='' .venv/bin/python -m uvicorn v2.api:app --host 127.0.0.1 --port 8511
```

또는 프로젝트 루트에서 `./start-v2.sh`를 실행하세요. 접속: http://127.0.0.1:8511. 위 명령은 기존 SQLite 데모 DB를 사용합니다. PostgreSQL을 사용하려면 `DATABASE_URL=''` 접두사를 제거하고 루트 `.env`에 실제 연결 정보를 설정하세요. 기존 `create_repository`가 PostgreSQL 어댑터를 선택하며, 이번 변경에서 PostgreSQL 실행 검증은 하지 않았습니다.

프런트 개발은 별도 터미널에서 `npm run dev --prefix v2/web`로 실행합니다. Vite의 `/api` 프록시는 8511 포트입니다. 기존 8510 포트가 사용 중이라 경동 V2의 기본 포트를 8511로 분리했습니다.

## 사용자 흐름

- 왼쪽: 지식문서 검색과 본문, 데이터허브 원본 테이블(10개씩 탐색).
- 중앙: 전체/프로젝트 선택, 대화, 근거 펼침, 새 대화, 실시간 음성.
- 오른쪽: 생산·품질 10개 / 문서·규칙 10개 추천질문, 세션별 최근 질문 20개.
- 모바일: 자료·질문 버튼으로 보조 패널을 열고 닫습니다.
- 직접 입력·추천질문·이력 재질문은 같은 요청 경로를 사용합니다. 이력은 원래 프로젝트를 함께 복원합니다.
- 프로젝트 변경·새 대화는 요청을 취소하고 늦게 도착하는 응답을 무시하며 마이크를 종료합니다. 서버가 이미 시작한 유료 요청까지 취소되는 것은 아닙니다.
- 데모는 키워드로 정해진 조회 도구를 선택합니다. 임의 질문의 의미를 AI로 분석하지 않습니다. AI 분석은 기존 Responses 도구 루프를 호출하고 최근 최대 12개 대화 메시지를 전달합니다.
- 프로젝트와 자재 LOT는 별개 식별자입니다. 수량·두께·공수·FAT 측정 단위는 원본 레코드로 확인합니다.

## 연결과 접근 제어

루트 `.env`를 읽습니다. 필요한 환경변수는 `v2/.env.example`에 있습니다. API 키는 서버에만 둡니다. 화면 설정의 접근 코드는 API 키와 별개이며 sessionStorage에 저장합니다.

로컬 예외는 연결 상대 IP와 요청 hostname이 모두 loopback일 때만 허용합니다. 외부 API 접속은 데모 조회를 포함해 `COCKPIT_ACCESS_TOKEN`이 필요합니다. 공유 접근 코드는 사용자 계정·조직 권한 시스템이 아닙니다. 신뢰 프록시 환경에서는 실제 클라이언트 IP 처리와 별도 사용자 인증을 배포자가 구성해야 합니다.

`DATABASE_URL` 지정 여부에 따라 기존 PostgreSQL/SQLite 어댑터를 선택합니다. 데이터는 모두 검증용 가상 자료이며 문서는 미승인 샘플로 표시됩니다. 실제 회사 데이터를 연결하면 출처·승인 상태·demo_data 메타데이터도 함께 변경해야 합니다.

실시간 음성은 WebRTC와 발화 종료 감지·끼어들기·음소거·종료를 지원하도록 구현했습니다. 실제 경동 조회 도구 스키마와 서버 핸들러를 제공하고 도구 결과는 화면 근거에도 남깁니다. 센서 스트리밍/설비 제어 기능은 포함하지 않습니다. HTTPS 또는 localhost와 마이크 권한이 필요합니다.

공식 구현 참고: [OpenAI WebRTC 연결](https://developers.openai.com/api/docs/guides/voice-webrtc). 모델 가용성과 유료 호출은 해당 계정에서 확인해야 합니다.

## 검증

```bash
.venv/bin/python -m pytest tests v2/tests -q
npm run build --prefix v2/web
```

기존 테스트 28개 통과·1개 건너뜀에서 API 테스트 7개를 추가했습니다. 합계 35개 통과·1개 건너뜀입니다. API 테스트는 임시 DB와 모의 음성 서버를 사용하며 실제 유료 호출을 수행하지 않습니다.

실제 유료 AI·음성, 마이크 실기기, PostgreSQL, Docker 배포는 이번 검증 대상에서 실행하지 않았습니다. 기존 루트 Docker/Compose는 Streamlit V1용입니다. V2 외부 배포는 별도 구성이 필요합니다.

브라우저 검증도 완료했습니다: 1440px 데스크톱 / 390px 모바일에서 문서 검색·본문, 테이블, 직접 입력·추천질문·이력 재질문, 프로젝트 전환, 새 대화와 근거 표시, 가로 넘침을 확인했습니다. 모의 WebRTC로 연결 실패 시 마이크 해제, 음소거/해제, 종료 후 트랙 정리와 지연 응답의 문맥 격리를 확인했습니다. 실제 음성 인식 품질·끼어들기 오디오 동작을 검증했다는 의미는 아닙니다.

서버가 실행 중이고 Playwright와 Chromium이 설치된 환경에서는 다음으로 브라우저 검증을 다시 실행할 수 있습니다. 별도 설치 위치는 `PLAYWRIGHT_MODULE` 환경변수로 지정할 수 있습니다. 기본 접속 주소를 바꾸려면 `KGT_URL`을 지정합니다.

```bash
node v2/tests/browser-smoke.cjs
node v2/tests/browser-lifecycle.cjs
```


## Hostinger Docker Manager

`docker-compose.v2.yml`과 `v2/Dockerfile`은 기존 `경동 조종석`(8501)을 재시작하지 않고 포트 8511에 V2를 별도 배포하도록 구성했습니다. SQLite 데모 DB는 named volume에 유지되고 샘플 데이터로 초기화됩니다. PostgreSQL 접속과 운영 데이터는 구성하지 않습니다.

새 애플리케이션 이름은 `kyungdong-agent-v2`로 사용합니다. Compose는 GitHub 공개 저장소의 `main`을 Docker 원격 빌드 컨텍스트로 가져옵니다. YAML 편집기의 URL 구성은 `https://raw.githubusercontent.com/superpjh-stack/KD_Agent_cockpit/main/docker-compose.v2.yml`을 사용합니다. 배포 환경에 `COCKPIT_ACCESS_TOKEN` 값을 지정하지 않으면 Compose 변수 검증 단계에서 시작을 거부합니다. 이 값은 외부 API 요청을 보호하며 앱 화면의 접근 코드 입력란에 같은 값을 입력합니다. OpenAI 기능은 `OPENAI_API_KEY` 서버 환경변수가 설정된 경우에만 활성화됩니다.

## 2026-10-11 실제 유료 AI·음성 검증

서버 `.env` 키와 임시 SQLite 샘플 DB로 실제 API를 호출했습니다. [검증 기록](../docs/paid-ai-voice-verification-2026-10-11.json)에 답변과 수신 통계를 남겼습니다.

- `gpt-4.1`: 자재 조회와 FAT 문서 질문 2건 모두 HTTP 200. 각각 약 3.2초/2.6초였고 원본 레코드·문서 근거를 반환했습니다. 자재 답변의 LOT `ML-260901`, 수량 `4 EA`, 두께 `12 mm`를 원본과 대조했습니다.
- `gpt-realtime-2.1` / `marin`: 실제 WebRTC 연결, 한국어 음성 인식, `get_material_status` 호출, 근거 화면, 한국어 답변 오디오 수신, 음소거/해제, 종료 후 트랙·연결 정리를 확인했습니다. 최종 수신은 113,046 bytes, 1,408 packets이며 오디오 에너지가 0보다 컸습니다.
- 첫 음성 답변이 조회시각을 근거 ID로 읽는 문제가 있어 지침을 수정했습니다. 수정 후 추가 유료 검증에서는 빈 조회 결과를 ‘일치하는 기록 없음’으로 설명했고 ID·수량을 만들지 않았습니다.
- 초기 AudioContext 음성 주입은 인식 대기시간을 초과했습니다. 이후 Chromium의 파일 기반 테스트 마이크로 성공했습니다. 물리 마이크·스피커 청취 품질, 실제 끼어들기, 모바일 실기기, PostgreSQL 및 외부 배포 검증은 포함하지 않습니다.

재실행은 실제 비용이 발생하며 명시적 환경변수가 있어야 실행됩니다. 연결 준비 시간을 고려해 앞에 약 8초 무음이 있는 한국어 PCM WAV를 준비하세요. 서버에는 키가 설정되어 있어야 합니다. Playwright가 별도 위치에 있으면 `PLAYWRIGHT_MODULE`을 지정합니다.

```bash
KGT_LIVE=1 KGT_URL=http://127.0.0.1:18521 \
KGT_TEST_WAV=/absolute/path/to/test-question.wav \
node v2/tests/browser-live.cjs
```

문자 검증을 반복하지 않고 음성만 검증하려면 `KGT_SKIP_TEXT=1`을 추가합니다. 결과 경로는 기본 `/tmp/kgt-live-report.json`이며 `KGT_LIVE_REPORT`로 변경할 수 있습니다. 테스트 브라우저는 종료되고 실제 마이크는 사용하지 않습니다.

## LangGraph 복합질문 (2026-11-11)

V2는 `CompoundGraph`의 계획 → 범위·인자 검증 → 최대 3개 동시 조회 → 결과 점검 → 종합 그래프로 동작합니다. AI 모드는 최대 두 번 계획하며 총 조회 12회로 제한합니다. 데모 모드는 다중 키워드 조회 결과를 표시하고 의미 기반 종합은 AI 모드에서 수행합니다. 기존 20개 질문에 복합질문 10개를 추가했습니다. 음성의 `analyze_manufacturing_question`도 같은 분석기를 사용합니다.

Python 3.12 환경 사용:

```sh
uv venv --python python3.12 .venv-v2
uv pip install --python .venv-v2/bin/python -r v2/requirements.txt pytest
./start-v2.sh
```

기존 `.venv`는 보존했습니다. Docker도 V2 requirements를 설치합니다. 로컬 검증 화면은 http://127.0.0.1:8512 입니다.

검증: Python 테스트 22개, TypeScript/Vite 빌드, 데스크톱 1440px·모바일 390px 브라우저 테스트와 모의 음성 수명주기 테스트 통과. 실제 AI 비교 질문에서 자재·입고검사·FAT와 문서 5개를 함께 조회했습니다. 실제 휴대폰 음성 및 Docker 실행은 미검증입니다.

초기 구현 한계: coverage는 조회 항목의 결과 유무를 표시하며 자연어 답변의 완전성을 증명하지 않습니다. 원시 테이블/클레임 도구는 그래프 계획에서 제외했습니다. 처리시간 상한에 도달하면 결과를 부분 반환하지만 이미 실행 중인 DB 스레드를 강제 종료하지는 않습니다. 모호한 후속 질문 확인은 모델 지침에 의존하며 별도 clarify 노드는 없습니다. 영구 체크포인터는 사용하지 않습니다.

### 복합질문·음성 안정성 보강

원래 질문과 계획의 요청 항목을 보존하고, 명시된 분야가 빠지면 기본 조회를 보완합니다. 최종 검증 노드가 항목별 답변 인용과 근거 인덱스를 점검합니다. 인용이 답변에 없거나 근거가 비어 있거나 검증 호출이 실패하면 완료로 표시하지 않습니다. 이 검사는 의미·수치의 절대 정확성을 보장하지 않으며 화면에서 추가 확인 항목을 구분합니다. 음성 요약은 앞부분 자르기 대신 검증 단계에서 별도로 생성합니다.

새 발화가 시작되면 브라우저 조회를 취소하고 이전 발화의 도구 결과·텍스트 이벤트를 무시합니다. 음성 출력을 비우고 응답 취소를 요청합니다. 이미 서버에서 실행 중인 DB/모델 호출의 중단 및 비용 취소는 보장하지 않습니다. 23개 Python 테스트와 지연 도구·이전 음성 이벤트를 주입한 모의 브라우저 테스트를 통과했습니다. 실제 기기 음성 검증은 별도입니다.

### 후속 질문 문맥과 비교표

‘그 프로젝트’, ‘해당 프로젝트’, ‘그럼’ 등의 후속 질문은 최근 사용자 질문에 명시된 프로젝트를 이어받습니다. 화면의 선택 프로젝트가 있으면 이를 우선하며, 질문에 명시한 새 프로젝트가 최우선입니다. 이전 답변이 임의로 언급한 ID는 문맥의 근거로 사용하지 않습니다. 여러 대상 중 하나를 가리키거나 ‘다른 프로젝트’의 대상이 없으면 확인 질문을 반환합니다. 이력은 현재 대화의 최근 12개 메시지 범위이며 새 대화·프로젝트 전환 시 초기화됩니다.

비교·종합 질문은 납기, 예상 원가, 자재, FAT의 조회 원본으로 표를 생성합니다. 원본 값과 단위를 보존하고 없는 값은 미확인으로 표시하며, 상세 분석은 표 아래에서 펼칩니다. 다른 분야는 기존 근거 표시를 유지합니다.
