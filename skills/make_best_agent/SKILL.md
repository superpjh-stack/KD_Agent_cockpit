# make_best_agent

경동글로벌텍 에이전트의 구현과 사용자 피드백을 재사용한다. 기존 프로젝트에서는 필요한 부분만 적용하고, 새 프로젝트에는 `assets/starter/`를 기반으로 회사명·자료·도구를 교체한다. 사용자가 지정한 제품과 기술을 우선한다.

## 작업 경로

- 코드 재사용·실행·검증: [구현 가이드](references/implementation.md)를 읽는다.
- 화면·음성·대화 동작: [제품 동작 기준](references/product-behavior.md)을 읽는다.
- 기존 구현이 있으면 실행 명령, 수정 상태, DB 및 API 구조를 먼저 확인한다. 기존 작업을 덮어쓰거나 사용자의 DB를 샘플로 초기화하지 않는다.
- 요청이 충분히 구체적이면 합리적인 구현 선택을 하고 진행한다. 추가 승인 절차나 존재하지 않는 외부 스킬을 필수 의존성으로 만들지 않는다.

## 핵심 구현 원칙

1. 업무 질문은 읽기 전용 도구로 확인하고 문서·DB 근거를 누적한다. 샘플 수치를 실제 회사 운영값으로 표현하지 않는다.
2. LangGraph에서 질문 분해, 범위·인자 검증, 다중 조회, 누락 보완, 종합, 요청별 답변 검사를 연결한다. 조회 성공과 질문 해결을 구분한다.
3. 프로젝트 범위는 명시된 ID, 사용자 선택(해당 UI가 있을 때), 검증 가능한 대화 문맥 순으로 결정한다. 모호한 대상을 임의로 선택하지 않는다.
4. 답변 인용과 근거 ID/인덱스를 확인하고 누락·실패·미확인을 표시한다. 모델 검사가 정확성의 증명이라고 주장하지 않는다.
5. 음성은 발화별 취소·이전 응답 격리, 중복 재생 방지, 별도 2–3문장 요약을 제공한다. 텍스트와 같은 업무 분석기를 사용한다.
6. 비교표는 원본 레코드에서 만들고 단위·0·미확인을 보존한다. AI가 생성한 수치를 테이블의 원본값으로 쓰지 않는다.
7. API 키는 서버에서만 관리한다. 브라우저에는 서비스 접근 코드만 전달한다. 장비 제어·발주·승인 실행으로 범위를 확장하지 않는다.

## 현재 기본 UX

- 이름: 경동 에이전트. 다른 회사 작업이면 변경한다.
- 왼쪽 추천질문·질의이력, 가운데 대화, 오른쪽 지식베이스·데이터.
- 기본 질문 그룹: 데이터 10개, 지식베이스 10개, 복합질문 10개. 제공 자료에서 실제 답할 수 있는 질문으로 교체한다.
- 호출명 없이 글·음성 질문을 받는다. 추천 질문에 호출명을 붙이지 않는다. 번호는 유지한다.
- 프로젝트 선택창은 기본 화면에서 생략한다. 필요하면 사용자 요청에 따라 추가한다.
- 빈 대화 영역은 ‘오늘 궁금한거 질문해!!’만 표시한다.
- 입력창을 하단에 유지하고 대화만 스크롤한다. 새 답변의 첫 부분을 보여주며 맨 아래로 자동 이동하지 않는다. 같은 음성 턴의 추가 근거·요약 때문에 읽는 위치를 바꾸지 않는다.
- ‘검증용 데모’, ‘데모 조회’는 상시 배지·선택 버튼에서 제외한다. 샘플 여부와 승인 상태는 펼칠 수 있는 출처 상세에 정직하게 남긴다.
- AI 설정이 있으면 AI 분석, 없으면 명확히 표시한 자료 조회를 사용한다. AI 실패를 성공으로 위장하지 않는다.

## 완료 기준

요청한 범위의 테스트와 빌드를 실행하고 결과를 보고한다. 복합질문 누락, 프로젝트 격리, 부분 실패, 음성 끼어들기의 지연 이벤트, 후속 질문·새 대화 초기화, PC·모바일 표와 스크롤을 우선 검증한다. 모의 WebRTC 통과와 실제 마이크 품질, 로컬 실행과 운영 배포는 구분해서 보고한다.

스냅샷은 출발점이며 모든 기능의 완성 보증이 아니다. 현재 제한과 재사용 시 보완할 사항은 구현 가이드에 기록되어 있다.
